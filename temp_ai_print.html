🌟 PART 1: 25 SIMPLE & FUNDAMENTAL AI QUESTIONS (1-Minute Answers)

Perfect for quick warm-ups and sanity checks during a 30-minute interview. Keep answers to 2–3 sentences.

S_Q1: What is an LLM (Large Language Model)?

An LLM is a deep learning model based on the Transformer architecture trained on massive amounts of text. Its core objective is predicting the next most likely token in a sequence, allowing it to understand, generate, and summarize natural language.

S_Q2: What is a Token?

A token is the basic unit of text that an LLM processes. It can be a whole word, a sub-word, or a single character. On average, 1 token is roughly 4 characters or about 0.75 words in English.

S_Q3: What is a Context Window?

The context window is the maximum number of tokens an LLM can take in as input and output combined in a single request. If a conversation exceeds the context window, earlier messages must be truncated or summarized, or the model fails with a token limit error.

S_Q4: What does "Temperature" do in LLM generation?

Temperature controls the randomness of predictions. At temperature 0.0, the model always greedily selects the single highest-probability token (deterministic). At higher temperatures like 0.7 to 1.0, it samples from lower-probability tokens, making responses more creative and diverse.

S_Q5: What is Top-P (Nucleus Sampling)?

Top-P limits the model's choices to the smallest set of tokens whose cumulative probability exceeds the threshold $P$ (e.g., top 90% of probability mass). Unlike fixed Top-K, Top-P dynamically adjusts how many candidate tokens to consider based on model confidence.

S_Q6: What is the difference between AI, Machine Learning, and Deep Learning?

AI is the broad umbrella concept of machines performing tasks that normally require human intelligence. Machine Learning is a subset of AI where systems learn patterns from data without being explicitly programmed. Deep Learning is a subset of ML using multi-layered artificial neural networks (like CNNs, RNNs, and Transformers).

S_Q7: What is Supervised vs Unsupervised Learning?

Supervised learning trains on labeled data (input $X$ paired with correct output $Y$) to predict targets (e.g., spam detection or house prices). Unsupervised learning trains on unlabeled data to discover hidden patterns or clusters on its own (e.g., customer segmentation or dimensionality reduction).

S_Q8: What is Overfitting and Underfitting?

Overfitting happens when a model learns training data too well, including its noise, and performs poorly on new test data (high variance). Underfitting occurs when the model is too simple to capture underlying patterns even on training data (high bias).

S_Q9: What is an Embedding?

An embedding is a list of numbers (a dense vector) that represents the semantic meaning of a word, sentence, or document. Words with similar meanings have vectors that point in nearly the same direction in vector space.

S_Q10: What is a Vector Database in simple words?

A vector database is a specialized database built to store embeddings and find the most similar ones in milliseconds using vector math (like cosine similarity), rather than exact keyword or row matching like SQL.

S_Q11: What is RAG (Retrieval-Augmented Generation) in plain English?

RAG is like an open-book exam for an LLM. Instead of relying solely on what the model memorized during training, you search your documents for relevant facts first, paste them into the prompt, and ask the model to answer based only on that context.

S_Q12: What is an AI Agent?

An AI agent is an LLM given goals, memory, and tools (like web search, a Python interpreter, or database queries). Instead of just generating text, the agent decides which tools to call in a loop until the user's objective is completed.

S_Q13: What is the difference between a System Prompt and a User Prompt?

The System Prompt sets the rules, personality, guardrails, and role of the assistant (e.g., "You are a customer support agent. Answer concisely"). The User Prompt is the actual query or message sent by the human.

S_Q14: What is Zero-Shot vs Few-Shot Prompting?

Zero-shot means asking the model to perform a task with no examples given. Few-shot means providing 2 or 3 input-output examples in the prompt to teach the model the desired format or reasoning style before asking the actual question.

S_Q15: What is Chain-of-Thought (CoT) Prompting?

Chain-of-Thought prompts the model to break down complex reasoning by explicitly stating: "Think step-by-step before answering." Generating intermediate steps significantly boosts accuracy on math, logic, and multi-hop questions.

S_Q16: What is a Hallucination and how do you stop it?

A hallucination is when an LLM produces an answer that sounds completely confident and fluent but is factually incorrect. We stop it using RAG with strict grounding prompts, lower temperature (0.0), and verification/critic guardrail agents.

S_Q17: What is the difference between Fine-Tuning and RAG?

RAG provides external knowledge at runtime without modifying model weights (fast, cheap, easily updated). Fine-tuning permanently updates the model's internal weights on specialized datasets to teach it a specific tone, format, or task syntax.

S_Q18: What is a Transformer in simple terms?

The Transformer is the neural network architecture behind all modern LLMs. Its breakthrough innovation is the Self-Attention mechanism, which allows the model to process all words in a sentence simultaneously and calculate how much each word relates to every other word.

S_Q19: What is Softmax?

Softmax is an activation function that converts a vector of raw numbers (logits) into a probability distribution between 0 and 1 that sums up to 1.0. The highest probability represents the model's top prediction.

S_Q20: What is LangChain?

LangChain is an open-source framework that helps developers build LLM applications by providing pre-built modules for prompt templates, document loaders, vector stores, and chains connecting LLMs to external APIs.

S_Q21: What is LangGraph?

LangGraph is an extension of LangChain designed for multi-agent workflows. It allows developers to build stateful, cyclic graphs where agents can loop back, retry failed steps, and maintain persistent state across multi-turn interactions.

S_Q22: What is a Loss Function?

A loss function measures the difference between the model's prediction and the actual true answer. During training, backpropagation uses this loss to calculate gradients and adjust weights so the loss decreases over time.

S_Q23: What is an Epoch and Batch Size?

An Epoch is one complete pass of the entire training dataset through the neural network. Batch Size is the number of training examples processed together in one forward and backward pass before updating weights.

S_Q24: What is Classification vs Regression?

Classification predicts a discrete category or class label (e.g., "Spam vs Not Spam", "Low vs High Risk"). Regression predicts a continuous numerical value (e.g., predicting house prices or temperature).

S_Q25: What is RLHF (Reinforcement Learning from Human Feedback)?

RLHF is the alignment process that turns a raw base model into a helpful chatbot. Human evaluators rank multiple model responses, a reward model learns these preferences, and reinforcement learning (PPO) tunes the LLM to maximize the reward.

🏛️ PART 2: 50 IN-DEPTH & ARCHITECTURAL AI QUESTIONS

SECTION 1: LangGraph & Multi-Agent Architectures (10 Questions)

Q1: What is a Cyclic State Graph in LangGraph, and why is it superior to linear chains?

Standard LangChain chains execute Directed Acyclic Graphs (DAGs) where execution flows in one direction: $A \rightarrow B \rightarrow C$. A Cyclic State Graph allows conditional edges to point backward ($A \rightarrow B \rightarrow A$), enabling feedback loops. This is essential for agent self-correction: an agent generates a response, a critic audits it, and if it fails validation, the graph loops back with error context rather than returning incorrect output to the user.

Q2: How does state management work in LangGraph? What is a Reducer?

State is represented as a shared schema (typically a Python TypedDict or Pydantic model). Every node is a Python function that takes the current state and returns a dictionary of updates. A Reducer defines how updates to a specific state key are merged. For example, Annotated[list, add_messages] tells LangGraph to append new messages to the history rather than overwriting the entire list.

Q3: In your Medical project, how did you implement parallel "Map-Reduce" inference?

Diagnosis (Pathology) and Treatment (Pharmacology) can be evaluated simultaneously on the same patient history. In LangGraph, I branched execution from the triage node to run both Dr. Diagnosis and Dr. Treatment asynchronously in parallel (the "Map" step). Once both returned their outputs, an aggregator node merged their independent analyses into a unified clinical brief (the "Reduce" step), reducing inference latency by ~40%.

Q4: Explain the architecture of the "Skeptic" Agent guardrail on your resume.

The Skeptic is a validator node placed between the clinical synthesis and the final output. It takes the proposed treatment plan and audits it against the patient's medical history (e.g., checking drug contraindications like prescribing NSAIDs/Aspirin to a patient with active peptic ulcers). If a conflict is found, a conditional edge routes back to the pharmacology node with an explicit warning note for correction. If safe, it routes to END.

Q5: How did you implement the "Self-Healing" execution engine in Aura?

When a sub-agent executes a shell/CLI command via Python's subprocess, I capture stdout, stderr, and the returncode. If returncode != 0, execution routes to a Diagnoser node. The LLM receives the failing command, system context, and raw stderr trace. It diagnoses the issue (e.g., missing dependency, incorrect flag), generates a remediation command, and loops back to the executor, capped at 3 retries to prevent infinite loops.

Q6: What is a Supervisor Agent and how does it coordinate sub-agents?

A Supervisor is an orchestration LLM node whose output is a tool call or routing decision. Given a user goal, it evaluates which specialized sub-agent (SysAdmin, Coding, Web Operator) is qualified to take the next step. It passes state to that sub-agent, awaits its response, and decides whether the overall goal is satisfied or if another sub-agent must be invoked.

Q7: What are LangGraph Checkpointers and why are they used?

Checkpointers persist the state of the graph at every step to a storage backend (in-memory, SQLite, or PostgreSQL). This enables: 1. Multi-turn conversational memory across independent API requests. 2. Human-in-the-Loop interruption (pausing execution for human approval and resuming from the exact checkpoint). 3. Time-travel debugging (rewinding to a previous state and replaying execution).

Q8: What is "State Cross-Pollination" mentioned in your Aura project?

In multi-agent systems, agents often work in silos. State cross-pollination means the outputs and tool findings from one sub-agent (e.g., the Web Operator finding an API documentation URL) are saved into the global shared graph state so the Coding agent can immediately use that context without having to perform redundant lookups.

Q9: How do you prevent infinite loops in cyclic agent graphs?

Two mechanisms: 1. Recursion limit: LangGraph has a built-in recursion_limit parameter in .invoke(config={"recursion_limit": 10}) that automatically halts execution if steps exceed the threshold. 2. State counter: Tracking an attempts: int counter in the state object. The routing condition checks if state["attempts"] >= max_retries: return "fallback_node".

Q10: What is the difference between LangGraph, AutoGen, and CrewAI?

AutoGen focuses on conversational multi-agent chats between agents. CrewAI uses role-based, sequential, or hierarchical task lists. LangGraph is lower-level: it gives you granular, deterministic control over the exact execution graph, state transitions, cycles, and checkpoints. For production software where you need predictable state machines, LangGraph is the industry standard.

SECTION 2: LangChain, RAG & Vector Databases (10 Questions)

Q11: Walk me through an end-to-end RAG pipeline.

  1. Ingestion: Documents (PDFs, Markdown, text) are loaded via document loaders.
  2. Chunking: Text is split into overlapping passages using recursive chunkers.
  3. Embedding: An embedding model converts text chunks into dense floating-point vectors.
  4. Storage: Vectors and metadata are indexed in a vector database (ChromaDB).
  5. Retrieval: User query is embedded, and vector similarity search (cosine/ANN) retrieves top-$k$ relevant chunks.
  6. Generation: Retrieved context + system prompt + user question are sent to the LLM to generate an answer grounded in the retrieved text.

Q12: Why is chunk overlap necessary in text splitting?

Natural language context does not end neatly at arbitrary character boundaries. If an important fact or sentence is split across two chunks without overlap, the semantic meaning in both chunks is degraded, and neither chunk may have a high enough cosine similarity score during retrieval. Overlap (typically 10-20% of chunk size) ensures continuity across boundaries.

Q13: What distance metrics are used in vector search, and when do you use each?

  1. Cosine Similarity: Measures the angle between vectors, ignoring magnitude. Best for text embeddings where document length varies.
  2. Euclidean Distance ($L2$): Measures straight-line distance. Sensitive to vector magnitude.
  3. Dot Product: Product of magnitudes and cosine angle. Best when embeddings are already normalized to unit length ($1.0$), as it is computationally faster than cosine.

Q14: What is the difference between Dense Retrieval and Sparse Retrieval?

Sparse Retrieval (e.g., BM25, TF-IDF): Matches exact keyword frequencies. Great for specific entities, part numbers, or exact codes, but fails at understanding synonyms. Dense Retrieval (Embeddings): Captures semantic meaning and concepts even with zero matching keywords. Hybrid Search: Combines BM25 and dense embeddings with Reciprocal Rank Fusion (RRF) for the best of both worlds.

Q15: What is Re-ranking in advanced RAG pipelines?

First-stage retrieval pulls a larger pool of candidates (e.g., top-25 chunks) using fast bi-encoder embeddings. Then, a cross-encoder Re-ranker (like Cohere Rerank or BGE-Reranker) processes the query and each chunk together through full transformer cross-attention, scoring their true semantic relevance. The top-3 highest-scoring chunks are passed to the LLM. This drastically reduces noise.

Q16: What is HyDE (Hypothetical Document Embeddings)?

When user queries are very short (e.g., "fast response time"), their embedding may not match the dense paragraphs in documentation. HyDE instructs an LLM to generate a hypothetical answer first. Even if factually inaccurate, this hypothetical document shares the vocabulary and structure of real documents. Searching with the hypothetical answer's vector yields significantly higher retrieval accuracy.

Q17: How does ChromaDB handle metadata filtering?

ChromaDB allows attaching a key-value dictionary to each document embedding (e.g., {"department": "cardiology", "source": "guidelines.pdf"}). During a query, you can pass a where clause: collection.query(..., where={"department": "cardiology"}). This filters the search space before or during vector comparison, preventing irrelevant domain chunks from contaminating results.

Q18: What is the Context-Aware Tier-1 Router on your resume?

Not all user queries require heavy RAG retrieval or deep agent reasoning. A Tier-1 Router inspects the user query: simple conversational queries ("Hello", "Who are you?") are routed to a fast, low-cost linear path with no retrieval. Complex, domain-specific, or high-risk medical questions are routed to the multi-agent RAG loop. This saves latency and API costs.

Q19: What causes Hallucinations in RAG, and how do you mitigate them?

Causes: Irrelevant context retrieved, conflicting chunks, or prompt phrasing that allows the LLM to rely on pre-trained knowledge. Mitigation: 1. Strict system prompting: "Answer ONLY using the provided context. If not present, state that you do not know." 2. High retrieval threshold: Drop chunks below a similarity score. 3. Grounding / Fact-checking: Secondary LLM pass verifying every claim against retrieved text.

Q20: When would you use RAG vs Fine-Tuning?

  • Use RAG when: Information changes frequently, you need exact citations/sources, you have budget/hardware constraints, or you want to eliminate hallucinations on proprietary data.
  • Use Fine-Tuning when: You need to change the model's behavior, style, tone, or syntax (e.g., outputting custom JSON, medical terminology style, or 3D prompt expansions), or teaching a small model a specific skill without bloating the context window.

SECTION 3: PEFT, LoRA & LLM Fine-Tuning (10 Questions)

Q21: What is Parameter-Efficient Fine-Tuning (PEFT)?

Full fine-tuning updates all billions of parameters in an LLM, requiring massive GPU VRAM (for weights, gradients, and optimizer states like Adam). PEFT techniques freeze the pre-trained model weights and only train a tiny fraction of parameters (typically < 1%), achieving comparable task performance with dramatically lower compute and memory.

Q22: Explain how LoRA (Low-Rank Adaptation) works mathematically.

For a pre-trained weight matrix $W_0 \in \mathbb{R}^{d \times k}$, LoRA freezes $W_0$ and represents its weight update $\Delta W$ as the product of two low-rank matrices: $$\Delta W = B \times A$$ where $A \in \mathbb{R}^{r \times k}$ and $B \in \mathbb{R}^{d \times r}$, with rank $r \ll \min(d, k)$. The forward pass becomes: $$h = W_0 x + \frac{\alpha}{r} (B A) x$$ Initializing $A$ with Gaussian noise and $B$ with zeros ensures $\Delta W = 0$ at the start of training.

Q23: What are Rank $r$ and Alpha $\alpha$ in LoRA?

  • Rank ($r$): The inner dimension of matrices $A$ and $B$. Common values are 8, 16, or 32. Lower $r$ means fewer trainable parameters and faster training; higher $r$ allows learning more complex task representations.
  • Alpha ($\alpha$): A constant scaling hyperparameter. The updates are scaled by $\frac{\alpha}{r}$. A common heuristic is setting $\alpha = 2 \times r$. It controls how strongly the adapter weights influence the frozen base model.

Q24: What layers/modules do you typically apply LoRA to in Transformers?

Primarily the attention projection weights: * Query ($q_proj$) and Value ($v_proj$) projections are the most common minimum setup. * Modern best practice (like QLoRA) targets all linear projection layers: $q_proj$, $k_proj$, $v_proj$, $o_proj$, as well as MLP gate and up/down projection layers ($gate_proj$, $up_proj$, $down_proj$) for better convergence.

Q25: In your PolyForge project, why did you fine-tune Qwen instead of prompt engineering?

Prompt engineering on every incoming request increases prompt token count, latency, and inference cost. By fine-tuning a small local Qwen model using LoRA on custom pairs of terse prompts mapped to rich 3D-geometric descriptors, the model internalized the domain grammar. It could expand inputs in single-digit milliseconds locally with zero API cost and 100% consistency.

Q26: What is QLoRA and how does it differ from standard LoRA?

QLoRA (Quantized Low-Rank Adaptation) quantizes the frozen base model weights down to 4-bit NormalFloat (NF4) precision while keeping the trainable LoRA adapter weights in 16-bit BrainFloat (BF16). It also uses Double Quantization and Paged Optimizers to prevent memory spikes. This enables fine-tuning a 70B model on a single 48GB GPU or a 7B model on a consumer 16GB GPU.

Q27: What is Catastrophic Forgetting and how does LoRA prevent it?

Catastrophic forgetting occurs when a neural network fine-tuned on a new task overwrites its previously learned general knowledge. Because LoRA freezes the original pre-trained weights $W_0$ completely and only updates adapter matrices, the base model's reasoning capabilities are preserved. Furthermore, adapters can be swapped or disabled at runtime.

Q28: How do you merge LoRA weights back into the base model for inference?

Using the PEFT library method model = model.merge_and_unload(). It adds the computed product $\frac{\alpha}{r}(B \times A)$ directly to the base weights $W_0$. Once merged, the model has the exact same architecture and inference latency as the base model, with zero added compute overhead from adapter branches.

Q29: What is the difference between SFT (Supervised Fine-Tuning) and DPO (Direct Preference Optimization)?

  • SFT: Trains the model on prompt-response pairs using cross-entropy loss to predict the next token (teaching the model what to say).
  • DPO: Aligns the model using pairs of (prompt, chosen response, rejected response). It optimizes the policy directly against human preferences without needing a separate reward model (unlike RLHF).

Q30: How do you format training data for Chat / Instruction models?

Using standardized chat templates (like ChatML or Llama-3 formatting). Each training example is structured with roles: <|im_start|>system\n...<|im_end|>\n<|im_start|>user\n...<|im_end|>\n<|im_start|>assistant\n...<|im_end|>. During loss computation, a label mask is applied so loss is only calculated on the assistant's tokens, not the prompt.

SECTION 4: Deep Learning, Transformers & PyTorch (10 Questions)

Q31: How does the Self-Attention mechanism work in Transformers?

For each token input vector, the model projects it into three vectors: Query ($Q$), Key ($K$), and Value ($V$). 1. Compute dot product between Query and all Keys: $Q K^T$. 2. Scale by $\sqrt{d_k}$ (prevents gradients from vanishing in softmax). 3. Apply Softmax to get attention weights (probabilities of how much each word attends to every other word). 4. Multiply attention weights by Values ($V$): $$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V$$

Q32: Why do we divide by $\sqrt{d_k}$ in Scaled Dot-Product Attention?

For large projection dimensions $d_k$, the dot products grow large in magnitude, pushing the softmax function into regions with extremely small gradients (gradient saturation). Scaling by $\frac{1}{\sqrt{d_k}}$ keeps the variance of the dot products at $1.0$, ensuring stable gradient flow during backpropagation.

Q33: What is the difference between Encoder-only, Decoder-only, and Encoder-Decoder architectures?

  • Encoder-only (e.g., BERT): Bidirectional self-attention. Excellent for text classification, embedding generation, and extraction.
  • Decoder-only (e.g., GPT, Llama, Qwen): Causal (masked) self-attention; tokens can only attend to previous tokens. Standard for generative AI and autoregressive text generation.
  • Encoder-Decoder (e.g., T5): Encodes input bidirectionally, then decodes output autoregressively. Used for translation and summarization.

Q34: What is the KV Cache in Transformer inference?

In autoregressive generation, generating each new token re-computes Key and Value vectors for all preceding tokens. The KV Cache stores the previously calculated Key and Value matrices in GPU memory so only the single new token's $Q, K, V$ are computed at each step. This converts generation time complexity from $O(N^2)$ to $O(N)$.

Q35: Explain the difference between Adam, AdamW, and SGD.

  • SGD: Updates weights in the negative gradient direction with a constant learning rate. Can get stuck in saddle points.
  • Adam: Adapts learning rates per-parameter using running estimates of the first moment (mean) and second moment (uncentered variance) of gradients.
  • AdamW: Fixes how weight decay ($L2$ regularization) is applied in Adam. Standard Adam adds weight decay to gradients before updating moments; AdamW decouples weight decay and applies it directly to weights, leading to significantly better generalization in Transformers.

Q36: What is Gradient Accumulation in PyTorch and when do you use it?

When a GPU does not have enough VRAM to hold a desired effective batch size (e.g., batch size 32 causes OOM), gradient accumulation splits it into smaller micro-batches (e.g., batch size 4). You run forward and backward passes for 8 micro-batches without zeroing gradients (optimizer.zero_grad()), and call optimizer.step() only after accumulating gradients across all 8 steps.

Q37: What is Mixed Precision Training (FP16 / BF16)?

Instead of storing all weights and activations in 32-bit floats (FP32), mixed precision stores activations and forward/backward passes in 16-bit (FP16 or BF16) while keeping a master copy of weights in FP32. This cuts VRAM usage by ~50% and speeds up matrix multiplications on Tensor Cores. BF16 has the same dynamic range as FP32, eliminating the loss scaling required by FP16.

Q38: What is Cross-Entropy Loss and how does PyTorch implement it?

Cross-entropy measures the performance of a classification model whose output is a probability value between 0 and 1. In PyTorch, nn.CrossEntropyLoss() combines nn.LogSoftmax() and nn.NLLLoss() in a single mathematically stable class. You pass raw unnormalized logits directly from the model, not probabilities.

Q39: What is Overfitting and what regularizations do you use in Deep Learning?

Overfitting is when a model learns noise and specifics of training data, failing on unseen test data (high variance). Techniques: 1. Dropout: Randomly dropping neurons during training. 2. Weight Decay ($L2$ regularization): Penalizing large weights. 3. Early Stopping: Halting training when validation loss starts increasing. 4. Data Augmentation: Artificially expanding training data diversity.

Q40: What are Positional Embeddings and why does a Transformer need them?

Self-attention is permutation-invariant: it treats tokens as an unordered bag of words. To give the model awareness of sequence order, positional information must be added. Modern models (like Llama and Qwen) use RoPE (Rotary Position Embeddings), which encodes position by rotating the Query and Key vectors in the complex plane, allowing models to generalize to longer context windows gracefully.

SECTION 5: TinyML, Embedded AI & Optimization (5 Questions)

Q41: What is TinyML and why is it important for IoT devices like ESP32?

TinyML is deploying machine learning models on resource-constrained microcontrollers (MCUs) with micro-watt power consumption. Advantages: 1. Zero network latency: Sub-20ms local processing vs hundreds of milliseconds over cloud networks. 2. Privacy: Sensor telemetry never leaves the device. 3. Reliability: Functions without internet/WiFi. 4. Power efficiency: Eliminates energy-expensive radio transmissions.

Q42: What is Post-Training Quantization (PTQ) down to INT8?

PTQ maps 32-bit floating-point weights and activations to 8-bit integers ($[-128, 127]$): $$q = \text{round}\left(\frac{r}{S}\right) + Z$$ where $S$ is the scale factor and $Z$ is the zero-point. This reduces model footprint by 75% (from 4 bytes to 1 byte per parameter) and allows running integer-only arithmetic, which is dramatically faster on microcontrollers that lack a Floating Point Unit (FPU).

Q43: How does the TFLite Micro memory architecture work on an ESP32?

Microcontrollers cannot use dynamic memory allocation (malloc/free) because heap fragmentation causes crashes in embedded systems. TFLite Micro uses a single statically pre-allocated memory chunk called a Tensor Arena (e.g., uint8_t tensor_arena[kTensorArenaSize]). The interpreter maps model tensors, intermediate activation buffers, and scratchpad memory within this single arena at initialization time.

Q44: What is the processing pipeline in your Gestura wearable gesture controller?

  1. Sampling: MPU6050 6-axis IMU reads 3-axis accelerometer and 3-axis gyroscope data at 50Hz (every 20ms) over the I2C bus.
  2. Pre-processing: Raw integer readings are normalized to unit variance. A sliding window of 20 consecutive readings (representing a 400ms gesture window) forms a tensor.
  3. Inference: The quantized INT8 TFLite model processes the window in < 20ms.
  4. Debounce & Action: Softmax output above a 90% confidence threshold triggers smart home commands over BLE.

Q45: How do you prevent overfitting on small sensor datasets in TinyML?

Sensor data is prone to sensor drift and user variations. Mitigations include: 1. Heavy data augmentation: Adding Gaussian jitter, time-warping, and scaling to IMU accelerometer signals. 2. Keeping architectures compact (e.g., 2-3 dense layers or 1D Conv layers). 3. Quantization itself acts as a regularizer by eliminating high-precision weight noise.

SECTION 6: LLMOps, Infrastructure & Production AI (5 Questions)

Q46: How did you prevent CUDA Out-of-Memory (OOM) errors in PolyForge?

Running heavy local text-to-3D generation models (Hunyuan3D) consumes significant VRAM. If multiple API requests hit the GPU concurrently, CUDA triggers an unrecoverable OOM crash. Solution: I decoupled the FastAPI web server from GPU execution using Celery and Redis. Celery workers assigned to the GPU queue run with --concurrency=1, guaranteeing that only one generation task runs on the GPU at any millisecond. Additional requests wait safely in the Redis queue.

Q47: What is LangSmith and how is it used in LLMOps?

LangSmith is an observability and tracing platform for LLM applications. It traces every step in an agent execution: exact prompts sent, raw responses received, latency per node, token counts, tool call arguments, and error traces. It allows visualizing the full LangGraph execution graph in production and running automated benchmark evaluations against test sets.

Q48: What is Model Context Protocol (MCP) and why is it a game-changer?

Open-sourced by Anthropic, MCP provides a universal, standardized protocol (over JSON-RPC via stdio or HTTP/SSE) for LLMs to communicate with tools, databases, and environments. Instead of developers writing custom integration code for every tool, MCP standardizes: 1. Tools: Dynamic discovery of executable functions. 2. Resources: Read-only access to files and databases. 3. Prompts: Reusable templates. It creates a decoupled ecosystem where an AI agent can plug into any MCP server.

Q49: What is Time to First Token (TTFT) vs Inter-Token Latency (ITL)?

  • TTFT: The time elapsed from when the user submits a prompt until the first token streams back. It is dominated by prompt processing (prefill) and RAG retrieval.
  • ITL: The average time between each subsequent generated token during streaming. In our hackathon project, using Groq LPUs reduced TTFT to ~200ms, making WhatsApp chat interactions feel instantaneous.

Q50: How do you evaluate whether a RAG system is actually performing well?

Using the RAG Triad framework: 1. Context Relevance: Are the retrieved chunks relevant to the user's question? (Evaluated by computing semantic similarity between query and retrieved chunks). 2. Groundedness / Faithfulness: Is the LLM's answer derived strictly from the retrieved context, or is it hallucinating? 3. Answer Relevance: Does the final answer directly address the user's initial question?

💻 HANDS-ON CODING PRACTICE FOR AI (The 5 Most Likely Live Tasks)

Challenge 1: Build a LangGraph Cyclic Agent with a Reviewer Loop

Scenario: Build an agent where a generator writes text, a reviewer checks length. If < 10 words, it loops back; otherwise ends.

from typing import TypedDict
from langgraph.graph import StateGraph, END

# 1. State Schema
class AgentState(TypedDict):
    task: str
    draft: str
    iterations: int

# 2. Generator Node
def generator_node(state: AgentState) -> dict:
    current_iter = state.get("iterations", 0) + 1
    # Simulates improving output on retries
    new_draft = f"Detailed solution for {state['task']} with comprehensive architecture" * current_iter
    return {"draft": new_draft, "iterations": current_iter}

# 3. Conditional Routing Function (Reviewer)
def should_continue(state: AgentState) -> str:
    word_count = len(state["draft"].split())
    if word_count >= 10 or state["iterations"] >= 3:
        return "approve"
    return "retry"

# 4. Construct Graph

Challenge S1: Compute Cosine Similarity (NumPy / Python)

Prompt: "Write a function that calculates the cosine similarity between two 1D vectors."

import numpy as np

def cosine_similarity(v1, v2):
    dot_product = np.dot(v1, v2)
    norm_v1 = np.linalg.norm(v1)
    norm_v2 = np.linalg.norm(v2)
    return dot_product / (norm_v1 * norm_v2)

# Quick Test

Challenge S3: Softmax Function from Scratch (Deep Learning)

Prompt: "Write a numerically stable Softmax function in NumPy."

import numpy as np

def softmax(logits):
    # Subtract max(logits) to prevent overflow in exp()
    exp_logits = np.exp(logits - np.max(logits))
    return exp_logits / np.sum(exp_logits)

# Test

Challenge S4: Sliding Window / Text Chunker (RAG)

Prompt: "Write a simple text chunker that splits a list of words into chunks of size K with overlap O."

def chunk_words(words: list, chunk_size: int = 4, overlap: int = 1):
    step = chunk_size - overlap
    chunks = []
    for i in range(0, len(words), step):
        chunk = words[i:i + chunk_size]
        if chunk:
            chunks.append(chunk)
    return chunks

# Test

def is_palindrome(text: str) -> bool:
    clean = "".join(c.lower() for c in text if c.isalnum())
    return clean == clean[::-1]
